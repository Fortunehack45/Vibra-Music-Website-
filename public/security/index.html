Security Policy

Vulnerability Disclosure, Cryptographic Storage & Release Integrity

Vibra Music enforces strict client-side security hygiene: zero hardcoded production secrets in source control, TLS-only transport, hardware-backed Android Keystore encryption for local tokens, and verifiable SHA-256 checksums on every signed release APK.

01.

Supported Versions & Patch Policy

Security fixes and dependency hardening patches are actively maintained exclusively on the current minor release line. Older releases do not receive backported security updates and users are advised to stay on the latest signed release.

  • Version 1.8.x (Current: v1.8.186): Actively supported. Receives security advisories, cryptographic library updates, and timely patch builds via Vibra_Music_Releases.
  • Versions < 1.8: Unsupported (End of Life). Users running legacy builds should upgrade to the current signed v1.8.x APK.
02.

Responsible Vulnerability Disclosure

If you discover a security vulnerability, credential leakage risk, QuickJS sandbox escape, or cryptographic flaw within Vibra Music or the Listen Together relay, please report it privately rather than opening a public GitHub issue or posting exploits in community chats.

Submit reports through GitHub Security Advisories on Fortunehack45/Vibra_Music or private maintainer channels. Maintainers aim to acknowledge legitimate vulnerability reports within 48 hours and coordinate a verified fix prior to public disclosure.

  • Required Report Details: Include a clear technical description of the defect, reproducible steps or proof-of-concept material, affected build/commit hash, and an objective assessment of potential user impact.
  • Coordinated Remediation: We commit to transparent credit in release advisories (unless anonymity is requested) once patched binaries and SHA-256 digests are published.
03.

Client Transport & On-Device Keystore Architecture

Vibra Music is architected to minimize its attack surface across both network transport and local persistence:

  • Strict TLS Transport Enforcement: Cleartext HTTP traffic is blocked globally in AndroidManifest.xml via android:usesCleartextTraffic="false", ensuring media metadata, authentication exchanges, and Listen Together WebSockets traverse encrypted HTTPS/WSS channels.
  • Android Keystore + Google Tink Encryption: Sensitive user tokens in EncryptedPrefs.kt are encrypted using EncryptedSharedPreferences backed by Google Tink AES-256 keysets hardware-bound to the device Android Keystore.
  • Zero Hardcoded Production Secrets: Optional developer or CI build keys (SUPABASE_URL, SUPABASE_ANON_KEY, SPOTIFY_SPDC, LASTFM_API_KEY, LASTFM_SECRET) are injected exclusively at build time via gitignored local.properties or GitHub Actions Secrets and never committed to source control.
04.

Credential Rotation & Incident Revocation

If a user or self-host contributor suspects that an optional third-party token or environment secret has been exposed, follow the repository remediation procedure immediately:

  • Spotify Session Tokens (sp_dc): Revoke active web sessions immediately via Spotify Account Overview ("Sign out everywhere") and wipe stored local tokens inside Vibra Music settings (clearSpotifyWebSession()).
  • Supabase / Self-Hosted Sync Keys: Rotate exposed project keys inside the Supabase dashboard and enforce Row Level Security (RLS) policies so anonymous keys can never query unauthorized records.
  • Git History Sanitization (Contributors): Removing a secret in a follow-up commit does not erase prior history. Contributors must rotate compromised credentials server-side immediately and use git-filter-repo or BFG Repo-Cleaner if sanitizing fork history.
05.

Verifying Official Signed Releases

Official Vibra Music binaries are distributed strictly through github.com/Fortunehack45/Vibra_Music_Releases. Do not install repackaged APKs from unofficial mirror sites or third-party download aggregators.

Before sideloading, compare the SHA-256 digest of your downloaded APK (arm64-v8a, armeabi-v7a, x86_64, or Universal) against the checksums.txt asset published alongside each tagged release.
